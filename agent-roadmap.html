Agent 学习路线

01 · 建立全局视角

先理解系统，再比较实现

适合已经能够阅读业务代码、调用模型 API，希望独立设计和迭代 Agent 的开发者。时间安排只是参考，以每阶段的验收标准为准。

基础准备：熟练使用 Python、Go 或 Node.js 中的一门语言；掌握 Git、Linux、HTTP、异步并发、数据库与自动化测试。结合研究助手实现一个有超时、结构化日志和错误处理的服务接口，检查这些基础能否落到代码上。

学习主线：理解基本机制 → 手写核心功能 → 阅读不同实现 → 补齐生产工程 → 用评估验证设计。

接收任务→读取状态→组织上下文→调用模型→执行工具→记录结果↺继续或结束
知识层核心问题学习内容
模型基础能力和限制从哪里来？Token、Transformer、推理、采样、结构化输出
控制逻辑谁决定下一步？Workflow、Agent loop、路由、规划、终止条件
工具与环境如何完成真实操作？Tool calling、参数校验、执行器、MCP、沙箱
上下文与知识每一步给模型看什么？Prompt、检索、历史裁剪、摘要、记忆
状态与运行时任务如何持续和恢复？状态机、Checkpoint、并发、取消、事件流
评估与运维如何证明有效？测试集、Trace、成功率、延迟、成本、安全边界

模型负责生成或决策；应用程序负责执行、保存状态和实施约束。理解这条职责边界，才能看懂不同框架背后的共同结构。

02 · 一个持续迭代的项目

技术资料研究助手

用户提出技术问题，Agent 搜索和读取资料，整理有来源的答案，必要时继续检索，并保存研究结果。

从本地文档搜索与读取开始，逐步增加多轮工具调用、检索与压缩、跨会话记忆、流式进度、暂停恢复、并行研究和自动评估。使用公开资料，在独立练习目录完成。

评估基线：整理约 20 个固定问题。以后更换模型、Prompt、检索策略或框架时，都用它们做对照。

第 1 周 · 基本机制

理解 Agent 的形态和模型边界

  • 区分单次模型调用、固定 Workflow 与自主 Agent，理解三者如何组合。
  • 理解 ReAct 中推理、行动与观察的交替过程。
  • 追踪工具声明、模型提出调用、程序执行、结果回传的完整交互。
  • 掌握 Token、上下文窗口、采样参数、结构化输出；了解预训练、指令微调和偏好优化分别改变什么。

动手实践

对同一批资料和问题，分别实现直接回答、固定检索后回答、模型决定是否继续检索。记录正确性、调用次数和耗时。

验收：能解释一个任务为什么适合固定流程，另一个为什么需要动态循环。

阅读资料
  • Building effective agents：理解架构模式和复杂度取舍。
  • Hugging Face Agents Course：先学习基础单元。
  • ReAct 原论文：先读问题、方法和示例。
  • Hugging Face LLM Course：按需补 Transformer、Tokenizer 和推理基础。
第 2 周 · 核心循环

手写一个最小 Agent

使用模型 SDK 和普通函数，先支持搜索文档、读取文档、保存报告三个工具。

  • 实现消息历史、工具声明与注册、参数解析和校验、调用分发、结果回填。
  • 处理最终回答、最大轮数、超时与失败；记录每轮输入、输出和耗时。
  • 处理一次响应中的多个工具调用，保证结果对应正确的调用。
  • 明确工具失败后允许模型修正参数的条件，以及必须终止的条件。

验收：不依赖 Agent 框架也能完成多轮调用；遇到无效参数和反复调用时，任务能够受控结束。

源码对照

阅读 smolagents，关注执行循环、工具执行、历史记录和终止处理，比较工具调用型与代码执行型 Agent。

第 3–4 周 · 上下文与知识

深入 RAG、上下文管理和记忆

每轮模型调用前，都要决定哪些信息应该进入有限的上下文。

能力学习内容实验
检索切块、关键词、Embedding、混合检索、重排、引用比较关键词与向量检索的命中情况
上下文管理历史裁剪、摘要、工具结果截断、按需读取比较完整历史、最近若干轮、摘要加最近历史
长期记忆写入、提取、去重、更新、召回、过期、用户隔离用户更正后，下一会话能否使用新事实

先建立关键词检索基线，再增加向量检索并记录收益。小规模练习可以直接计算相似度，按实际存储和查询需求引入向量数据库。

区分四类数据

  • 任务状态：当前进行到哪一步。
  • 会话历史：发生过哪些交互。
  • 长期记忆：未来会话需要保留的事实或偏好。
  • 知识库：可以检索的外部资料。

它们可以共享存储设施，但生命周期和读写规则不同。

验收：能判断回答错误来自资料缺失、检索未命中、上下文遗漏，还是模型使用证据错误。

阅读资料

Effective context engineering for AI agents：重点看按需获取信息、上下文压缩和结构化笔记。

第 5 周 · 工具与协议

设计可靠工具，理解 MCP 与 Skills

  • 设计清晰的名称、描述、参数结构和返回格式；控制分页、粒度和结果长度。
  • 区分参数错误、业务失败和网络故障；判断哪些操作可重试，哪些需要幂等保护。
  • 隔离外部文档中的指令；理解代码执行的文件、网络、凭据与资源边界。
  • 将一个已有工具接成 MCP，理解 Host、Client、Server 以及工具发现和调用过程。

MCP 负责连接外部能力，Agent 的决策和权限控制仍需要系统设计。

补齐 Skills 的实现机制

将研究报告流程封装为一个 Skill：用元信息描述适用场景，按需加载操作说明、模板与脚本。追踪发现、选择、加载和执行的过程，验证版本管理与脚本权限。区分 Skill 提供的任务知识、工具提供的操作能力，以及 MCP 提供的连接协议。

验收：画出模型提出调用、权限检查、实际执行、结果回传的完整链路，解释 MCP 接入前后改变了哪一层。

阅读资料
  • MCP 架构文档
  • Agent Skills 官方文档：目录结构与按需加载。
  • Writing effective tools for agents
第 6–7 周 · 运行时工程

让任务能够持续、取消和恢复

学习显式状态与转换、Checkpoint、人工介入、并行执行、超时取消、流式事件、重试与副作用，以及会话隔离和并发更新。

动手实践

用 LangGraph 再实现一次手写版本，比较状态、恢复与执行控制。重点理解框架解决的问题。

生产性能与可观测性

补齐任务队列、并发上限、限流与背压、租户隔离，以及模型服务失败时的降级策略。为模型和工具调用关联 Trace，分别记录首个有效事件延迟、总耗时、P95 延迟、成功率和单任务成本；通过并发压测定位模型、检索或工具的瓶颈。

四个故障实验

  1. 工具很慢时取消任务，后台是否真正停止？
  2. 进程重启后，任务能否从持久化状态恢复？
  3. 报告已保存，但保存执行结果前进程崩溃，恢复后会怎样？
  4. 中间进度是否在任务完成前到达消费端？

保存了 Checkpoint，并不自动保证外部操作只执行一次。要沿真实执行链路检查重跑和副作用。

验收：能说明状态保存在哪里、恢复时哪些步骤会重跑，以及副作用如何处理。

阅读资料
  • LangGraph overview：编排和运行时。
  • LangGraph persistence：线程状态与跨线程存储。
第 8 周 · 评估与迭代

用证据判断优化是否有效

将问题集扩充到约 30–50 条，覆盖单文档回答、多文档综合、信息不足、资料矛盾、工具故障、长历史、用户更正和外部干扰指令。

为每条样例记录预期事实、证据和必要约束，允许开放任务存在多种有效执行路径。

指标作用
任务成功率用户目标是否完成
证据与引用正确性结论能否被资料支持
工具调用错误率接口和决策是否可靠
耗时、调用次数、Token 成本收益是否值得
重复运行的波动单次成功能否稳定复现

建立失败轨迹到回归样例的闭环：记录模型、Prompt、工具和数据版本，按规划、检索、工具、状态管理归因。对比实验固定其余变量，分别衡量单个组件和端到端任务；上线后关注用户目标完成率与人工接管率。

能用规则判断的内容优先用规则；语义判断可以引入模型评分并抽样人工核对。保留一部分未参与调优的验证样例。

验收：修改 Prompt、检索方式或模型后，能用同一套样例说明收益、代价和退化点。

阅读资料

Demystifying evals for AI agents

第 9–10 周 · 架构选择

比较单 Agent、Workflow 与多 Agent

在同一个研究任务上，比较单 Agent 顺序完成、固定并行检索后汇总、主 Agent 动态拆分并委派子任务。

  • 观察任务拆分、上下文隔离、结果汇总、失败传播和成本。
  • 用评估集判断多 Agent 在哪些任务上有实际收益。
  • 比较 ReAct、先规划再执行（Plan-and-Execute）与生成代码执行（CodeAct），关注计划失效后的重规划和执行安全。
  • 理解长任务 Harness：模型外部的任务清单、工作文件、检查点、验证器与恢复逻辑。模拟跨会话继续任务，检查目标、证据与未完成事项是否保留。
  • 了解 A2A 的 Agent 发现、任务状态与结果交换，比较跨服务协作和进程内委派的工程成本。

验收：写一页架构决策说明：任务特点、方案选择、成本，以及支持选择的实验结果。

源码对照

Deep Agents：理解长任务运行环境如何组合各项能力。协议部分阅读 A2A 官方文档。

03 · 开源实现与课程

带着问题阅读源码

顺序 / 项目阅读目标
1. mini-swe-agent最小循环如何与真实执行环境交互
2. smolagents工具、模型适配、执行步骤和代码执行

每次只追一条请求：入口 → 上下文构造 → 模型调用 → 工具执行 → 状态更新 → 输出，然后沿同一路径追一个失败案例。固定版本或 commit，记录实现，方便后续比较。

中文教材可用 Datawhale《Hello Agents》，课程主线可选 Hugging Face Agents Course。SDK 用法与安装版本不一致时，以对应版本的官方文档为准。

05 · 完成主线后的进阶方向

按目标选择深挖方向

平台与运行时工程

深入操作系统进程与资源限制、容器隔离、任务调度、持久化与一致性、可观测性和容量规划。将研究助手部署为多用户服务，验证限流、取消、进程退出后的恢复，以及不同用户的文件和记忆隔离。

验收：提供架构图、负载条件、性能结果和故障恢复记录，说明瓶颈和扩容方式。

算法与模型后训练

  1. 训练基础：补齐 PyTorch、梯度与优化器、Transformer、训练和推理区别，再学习 LoRA 等参数高效微调方法。
  2. 轨迹数据与 SFT：整理工具调用成功与失败轨迹，明确筛选、标注和去重规则；按任务来源划分训练与测试集，防止同源泄漏。
  3. 奖励与 RL：理解状态、动作、奖励、策略和 rollout；学习 PPO / GRPO 的目标与差异，理解多步工具交互中的结果奖励、过程奖励和奖励投机。
  4. 对照实验：固定工具与评估环境，比较基础模型、Prompt 优化和 SFT 模型的任务成功率、泛化、成本；再评估是否值得加入 RL。

验收：能解释失败源于系统实现、数据还是模型能力，并给出独立测试集上的训练前后结果。

进阶资料与源码阅读
  • Hugging Face TRL：从 SFT 的数据格式与训练流程入手，再阅读奖励建模、DPO 和 GRPO。
  • CloudWeGo Eino：作为 Go 工程方向的源码对照。
  • Deep Agents：沿任务规划、上下文和子任务执行链路阅读。

论文复现与技术表达

选择一个与研究助手相关的方法，固定论文版本、数据和基线，完成最小复现与消融实验。整理设计文档、复现步骤、失败案例和性能报告；开源贡献可以从有回归验证的实际问题修复开始。

学习安排按掌握程度调整；资料与接口以所用版本的官方文档为准。
