哈希

把反复查找的问题，变成按键定位。先想清楚：键代表什么，值存下标、次数，还是一组结果。

1两数之和简单›像在舞会上找搭档：看到一个数，就问登记簿里有没有它缺的另一半。

一步步推导

  1. 维护“数值 → 已出现下标”的哈希表。
  2. 遍历 x，先查 target−x；找到就返回两个下标。
  3. 没有搭档才登记 x，这保证同一元素不会被使用两次。

跟着例子走一遍

[4, 7, 1], target=8
4：找4，未登记 → 记下4
7：找1，未登记 → 记下7
1：找7，命中 → 返回[1,2]

容易踩的坑：先查后存；重复值也可能构成答案，例如[3,3]。

复杂度：时间 O(n)，额外空间 O(n)；哈希操作按均摊 O(1) 计。

双指针

两端或快慢指针之间始终维护一个约束。移动指针之前，解释为什么被丢弃的候选不可能更好。

283移动零简单›像整理书架：好书依次向左靠拢，空位自然留在最后。

一步步推导

  1. write 指向下一个非零数应放的位置。
  2. read 扫描数组，遇到非零就写入 nums[write] 并前进 write。
  3. 扫描结束，将 write 后面的格子填零。

跟着例子走一遍

[0,4,0,2] → 非零依次写入前两格
前缀[4,2]固定 → 尾部补零 → [4,2,0,0]

容易踩的坑：保持非零元素相对顺序；覆盖写后仍需清理尾部。

复杂度：时间 O(n)，额外空间 O(1)。

11盛最多水的容器中等›两块挡水板中，矮的那块决定水位；想变大，先给短板换个位置。

一步步推导

  1. 左右指针夹住数组两端，计算 min(两高度)×间距。
  2. 移动较矮的一端；保留它只缩短宽度，面积不会更好。

5和4：4×1=4 → 最佳6

容易踩的坑：移动高板没有改善上限；相等时任选一端移动即可。

复杂度：时间 O(n)，空间 O(1)。

滑动窗口

窗口代表连续区间。右端扩张探索，左端收缩恢复条件；固定窗口与可变窗口的边界规则不同。

3无重复字符的最长子串中等›开一扇不允许重复乘客的车窗：新人撞名，就从左边请人下车。

一步步推导

  1. 右指针逐个加入字符，用计数或集合记录窗口。
  2. 若当前字符重复，移动左指针并移除字符，直到重新合法。
  3. 每次合法时用 right−left+1 更新最长长度。

跟着例子走一遍

abca → abc合法，长度3
加入a重复 → 删掉左端a
窗口变为bca，仍长3

容易踩的坑：求连续子串；收缩要用while，左指针只能前进。

复杂度：时间 O(n)，空间 O(min(n,Σ))；Σ为字符集大小。

560和为 K 的子数组中等›把路程画成里程碑：两块里程碑的差是 k，中间这段就符合要求。

一步步推导

  1. 设前缀和 S，目标是找此前出现过多少次 S−k。
  2. 计数表先放入0出现1次，代表数组开始前的空前缀。
  3. 每读一个数，先累加匹配次数，再登记当前 S。

普通数组

从前后缀、排序和原地变换中寻找结构。很多数组题的关键是给每个位置定义清楚职责。

53最大子数组和中等›背包里若装着负贡献，就放下它，从当前数字重新出发。

一步步推导

  1. 定义 end 为“必须以当前位置结尾”的最大子数组和。
  2. 转移 end=max(x,end+x)：新开一段，或接在上一段后面。
  3. 全局答案取所有 end 的最大值。

跟着例子走一遍

[-3,4,-1,2,-5]
end依次为-3,4,3,5,0
最大5，对应[4,-1,2]

容易踩的坑：全是负数时答案是最大的那个负数；不能把全局答案初始化为0。

复杂度：时间 O(n)，空间 O(1)。

  2. 边界dp[i][0]=i、dp[0][j]=j；末尾相同则沿对角继承。

复杂度：时间 O(mn)，空间 O(mn)，可用滚动数组压缩。

31下一个排列中等›像给数字里程表找下一格：尽量晚地升高一位，再把后面的数字排成最小。

一步步推导

  1. 从右往左找第一个nums[i]<nums[i+1]，右侧因此是非递增后缀。
  2. 若找到i，在右侧从后往前找第一个大于nums[i]的数并交换。

287寻找重复数中等›把数组值当作“下一站下标”，重复数字让两条路汇入同一站，形成可追踪的环。

一步步推导

  2. 用Floyd快慢指针找到环内相遇点。
  3. 一个指针回到0，两个都走一步，再相遇的下标就是重复值。

入口2就是重复数字2

复杂度：时间 O(n)，额外空间 O(1)，无需修改数组。
